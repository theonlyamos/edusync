## Available flows

- Teachers: published lesson/objective selection, manual mixed questions, approved quiz import, optional AI drafting, deadline/support settings, preview, publication to selected students, submission roster, individual extensions, private marking drafts, explicit individual/batch feedback release, revision requests, duplication, archive, and assignment insights.
- Students: assigned homework list, brief, per-question work with autosave and browser recovery, private attachments, pinned lesson reference, optional concept hints, answer review, immutable submission receipt, released marks/rubric feedback, revision work with prior feedback, attempt history, and points-weighted performance.
- Entry points: homework links in both sidebars, dashboards, and lesson detail pages. Existing assessments remain separate.

## Deployment prerequisites

1. Both `supabase/migrations/20261009102533_lesson_homework.sql` and `supabase/migrations/20261009120603_homework_multiple_answers.sql` are applied to the configured `insyte` project. For another environment, apply the base migration before the follow-up, or only the missing follow-up if homework is already installed. The first adds service-only tables/RPCs, the private `homework-files` bucket, and a restrictive browser policy. The follow-up adds multiple-answer validation/scoring without rewriting existing work. Missing migrations prevent homework requests/help-policy checks or multi-answer submissions from succeeding. After explicit user approval, the connector's server-assigned history versions `20261009122205` and `20261009122216` were aligned with local versions `20261009102533` and `20261009120603`, respectively. Verification confirmed both matching records, preserved migration metadata, and unchanged unrelated history.
2. Configure the lesson’s organization and active teacher/student organization memberships. Student grades must match the published lesson grade. Assignment is limited to 200 selected students per homework; eligibility comes from the school roster because this repository has no general class roster.
3. Publish the source lesson in Lesson Studio. Homework stores its published version, objectives, questions, rubric, and private marking keys. Drafts can be created before the lesson has an organization; saving after school configuration updates that draft’s organization.
4. Use the existing server Supabase service credentials and AI configuration. Teacher drafting and student hints use the existing AI completion and school quota services; unavailable AI does not block manual work or grading.
5. Verify the complete teacher/student flow with actual authenticated accounts and private Storage in the target environment before release. The local browser harness replaces the API and application shell; it does not prove live provider/authentication behavior.

## Product decisions and limits

- Deadline inputs explicitly use UTC; the selected IANA timezone controls display. This avoids silently interpreting daylight-saving gaps/overlaps. Teachers must convert local school times when entering deadlines.
- Choice questions support one answer (`multiple_choice`, radio buttons) or multiple answers (`multiple_select`, checkboxes). Both offer up to eight distinct options. Teacher-only keys match the selected response type. Multiple-answer provisional scores require the exact correct set, regardless of selection order; missing or extra choices score zero provisionally. Teachers may award partial credit with an override reason and approve all released marks. Published lesson multi-answer quizzes retain their type and key arrays when imported. Existing single-answer questions and submitted work remain compatible.
- General AI generation/tutoring tools pause while the student has an editable published homework attempt, directing help through the assignment’s concept-hint policy. Closed/archived/submitted work does not pause them. This affects help on other topics while an attempt is open. External AI and previously issued live tokens cannot be retroactively controlled by this feature.
- Students see released grade snapshots. Private corrections remain hidden until rerelease. Bulk release includes only changed complete grades on each student's latest attempt; unchanged releases retain their original timestamp. The latest released attempt contributes once to performance, even while a newer revision is unfinished. Objective evidence stays separate when its pinned revision changes.
- Attachments commit together with their answer IDs and answer version. Reloading recovers an upload whose response was lost. Signed access lasts one minute; file content/type/size and ownership are checked server-side. Revision attempts retain prior files without modifying submitted history.
- Reports fetch database pages rather than trusting a response cap. Limits produce an explicit error rather than partial totals: 5,000 attempts per detail/performance report, 20,000 rows in list summaries, 5,000 school members, and 2,000 source lessons. Larger histories need a server-side report/roster pagination feature.
- Draft questions must pass validation before server saving. Teacher editing is disabled during saves; ordinary link navigation warns about unsaved teacher work. Student browser recovery remains scoped to the signed-in student and attempt on that device and excludes deleted attachment references while preserving writing. Save teacher drafts before browser history navigation; actual Next.js history traversal was not checked.
